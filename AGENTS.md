# Working in diffle

Diffle is a local Git review app: a Rust server (`crates/diffle`, axum on tokio) owns repository state; a React client renders diffs with `@pierre/diffs`; comments can become an agent prompt or a pending GitHub review. Keep `README.md` focused on installation, core workflows, and user-visible constraints. Let `--help`, code, and tests carry exhaustive detail.

## Find the owner

- `src/shared/protocol.ts`: the only client/server contract. Define cross-boundary fields here first.
- `crates/diffle/protocol.generated.json` and `build.rs`: the Rust side of the contract, generated. `test/scripts/protocol-schema.test.ts` exports `protocol.ts` to the JSON file (`npx vitest run test/scripts/protocol-schema.test.ts -u` after a protocol change) and `build.rs` turns it into Rust with typify (`crate::protocol`). Numbers on the wire are `.int()` unless they truly are fractional. An optional array becomes a defaulted `Vec`, so a route that must tell absent from empty reads its own request struct. The crate's version comes from `package.json`.
- `crates/diffle/src/git/`: all Git execution (`exec.rs` is the one module that spawns git; `catfile.rs` the shared `cat-file --batch`). Use explicit argv and preserve stable, NUL-delimited parser inputs where applicable.
- `crates/diffle/src/session/`: the active review, snapshots, comments, watcher, and serialized transitions: `mod.rs` the queue, `transitions.rs` entering a review and showing a slice of its range, `refresh.rs` reloads and iterations, `files.rs` the allowlisted reads, `github.rs` discovery and export.
- `crates/diffle/src/snapshotter.rs`: derives trees, changed files, and patches for one mode; `generated.rs` flags generated files.
- `crates/diffle/src/mode/`: `revspec.rs` parses revision arguments, `resolve.rs` turns a request into a `Review` and a range into endpoints, `pr.rs` fetches a pull request into session refs, `view.rs` resolves the slice a review shows (a commit, the uncommitted changes, an interdiff or one of its pairs; `rangediff.rs` replays and pairs), `keys.rs` derives where its comments live.
- `crates/diffle/src/server/`: HTTP and the `/ws` hub; `routes/` holds the route groups, `guard.rs` the Host/Origin check, `assets.rs` the embedded client.
- `crates/diffle/src/comments/`: persistence, relocation, import, and prompt formatting.
- `crates/diffle/src/github/`: `client.rs` resolves the token and owns the one HTTP client (octocrab over reqwest; `gh` is spawned for `gh auth token` alone); `pulls.rs` names pull requests; `review.rs` builds and exports pending reviews through `pending_review.rs`, its GraphQL calls; `metadata.rs` discovers a comparison's pull request.
- `crates/diffle/src/lsp/`: `registry.rs` and `projects/catalog.rs` define every server (command, languages, settings) and resolve which to start; `process/` spawns one and owns its status, with `output.rs` keeping its log, notice, and progress; `documents.rs` keeps its open documents in step with the snapshot; `locator.rs` maps its URIs back to snapshot paths; `bridge.rs` asks it the LSP requests, through the wire shapes in `shapes.rs`; `pool.rs` routes by language and merges with `merge.rs`. `lsp_blocker` (`crate::protocol`, ported from `src/shared/lsp.ts`, which the client uses) is the one place deciding why a query cannot run.
- `crates/diffle/src/cli/`: clap arguments, the run (`serve.rs`), and the subcommands.
- `src/client/api.ts`: the only client module that knows URLs.
- `src/client/store.ts`: Zustand state and effects; guard async commits with the current generation.
- `src/client/model.ts`: pure state functions and item identity, kept separate to avoid store cycles.
- `src/client/review/ReviewPane.tsx`: `CodeView` rendering, measurement, and scroll placement.
- `src/client/ui/dialog.tsx`, `tooltip.tsx`: shadcn components on Base UI (`components.json`, `@/` alias). We own them, restyled to the theme tokens; add another with `npx shadcn add`, then restyle it the same way. Not `button`: it would collide with `Button.tsx` on case-insensitive filesystems. `TipSurface` hangs a tip at a viewport box; `TitleTooltips` turns every `title` into one.
- `scripts/lib/quality-gate/`: the commit gate. `guards.ts` holds the pure rules, `tree.ts` reads the working tree, `run.ts` words the messages.

## Preserve these invariants

- `Session` alone advances `Snapshot.version`; mode switches, refreshes, and context changes stay serialized.
- `Snapshot.tree` is the new-side allowlist. File and LSP reads go through `Session::read_side`; it also maps a rename's old path. The one exception is a file outside the snapshot that a language-server result named (`Locator::read_external`, `Locator::origin`): `/api/file` serves it on the new side, and the servers that named it are asked about it.
- A `Review` names what is reviewed, nothing resolved; the `Snapshot` carries the hashes, `follows` and `commentKey`. Persist review state under `<git-dir>/diffle/`, keyed by `Snapshot.commentKey`; keep the worktree untouched.
- PR fetches use session-owned `refs/diffle/` refs. `GitRepo::fetch` must reject destinations outside them.
- Treat rendered `FileDiffMetadata` as immutable. Hydrate with `hydratePartialDiff('clone', ...)`, replace the store entry, and change its generation-backed item id.
- Every async boot, refresh, or mode-switch result commits only while its generation is current.
- Navigation jumps land at the fixed gaze point with `placeCursor(..., 'eye')` or `align: 'eye'`.
- `ReviewPane` resolves estimated jump layouts synchronously: scroll, `render(true)`, then reissue the measured offset before paint. Avoid cross-frame correction.
- Handled keys stop propagation in `useKeymap`; `CodeView` cancels pending scroll on propagated keydown.
- The keymap runs the store's `escape()` on Escape and lets the key through, so a Base UI dialog also closes. A dialog whose Escape does more than close (References leaves a peek first) ignores the `escape-key` reason in `onOpenChange`.
- User input errors are `Error` variants (`Revspec`, `Git`, `Github`, ...; `Error::is_user_error`) or clap usage errors and exit 2; `Error::Other` is the unexpected kind and exits 1.
- Status goes to stderr through `crate::status!`, which never panics on a closed stream; stdout carries only the prompt at shutdown.

## Renovate cleanly

- Drop backwards compatibility: replace old paradigms directly with cleaner solutions instead of adding shims or legacy support code. Rip off the bandaid; announce breaking changes in your output with `💥 Breaking: <explanation>`.

## Verify changes

- Run `pixi run lefthook-run` (format, lint, typecheck, clippy and the quality gate over every file), `pixi run test-node`, `pixi run test-rust`, and `pixi run build-release` before finishing. The pixi tasks are the entry points, locally and in CI; underneath, npm scripts cover the client alone and cargo owns the server.
- `pixi run e2e` builds the client and the release binary that embeds it, then runs the suite over that binary; `DIFFLE_BIN=<path>` names another build. A debug build is too slow for the suite's parallel load.
- Never run the e2e tests (`pixi run e2e`) unprompted, not even after a client change. Run them only when the user asks or when you edited `test/e2e/`.
- Prefer tests that produce something a reviewer can judge: a screenshot, an accessibility tree, a prompt, a payload. Server tests (`crates/diffle/tests/`) use temporary real Git repositories (`tests/common`), and language-server tests drive `test/lsp/fake-lsp.mjs` with `node`; e2e tests (`test/e2e/*.spec.ts`) drive a real diffle over the fixture repository (`test/fixture/repo.ts`) in Chromium and compare against snapshots under `__snapshots__/`; text outputs use `toMatchFileSnapshot`, or on the Rust side insta (`crates/diffle/tests/snapshots/*.snap`; review changes with `cargo insta review`, or accept them all with `INSTA_UPDATE=always cargo test`). Do not stub the viewer or the API in client tests: write an e2e scenario instead. The one exception is `test/client/store.test.ts`, whose deferred-promise races a browser cannot provoke reliably.
- The fixture repository hashes the same everywhere; `test/fixture/repo.test.ts` pins the hashes. Changing its history means updating the pins and re-accepting the screenshots that show it. `npm run fixture -- <dir>` builds it for hands-on testing.
- The e2e browser is always Playwright's Linux Chromium in a Docker container (`compose.yml`; `test/e2e/browser-server.ts` starts and stops it, `DIFFLE_BROWSER_WS` names one running elsewhere), while the runner and diffle run natively, so screenshots match CI on any host. Run `pixi run e2e` and inspect the persisted report with `pixi run e2e-report`. Accept intended changes with `pixi run e2e --update-snapshots` or the `Update snapshots` workflow; the PR gets a snapshot report comparing before and after. `pixi run e2e -g <pattern>` runs a few scenarios while iterating.
- When CI's e2e job fails, it regenerates the failed scenarios' snapshots and uploads them as the `e2e-snapshots` artifact. Commit them onto the PR's branch with `gh workflow run update-snapshots.yml -f pr=<number>` (it waits for the head commit's e2e job), follow it with `gh run watch "$(gh run list --workflow update-snapshots.yml --event workflow_dispatch --limit 1 --json databaseId --jq '.[0].databaseId')"`, then `git pull`. Inspect the `e2e-results` artifact or the snapshot report before accepting. The bot's push reruns CI.
- The README GIF and diffle.app's videos are takes of real diffle: `npm run videos [-- <scene>]` (`scripts/record-videos.ts`) re-records them into `.github/assets/videos/`. Re-record the scenes a change alters (a shortcut, a moved control, a reworded hint) in the same PR and look at the frames; diffle.app copies them from the next release.
- Use `cargo run -- working --no-open` for a local source run. A debug build reads `crates/diffle/client` from disk, so `npm run build` and a reload show a client change; a release build embeds it.
- `THIRD_PARTY_NOTICES.md` ships in every archive and npm package; `scripts/licenses.ts` writes it from three sources: the fonts (`scripts/licenses-fonts.md`), the packages the client build bundled (the licence plugin in `vite.config.ts` lists each bundle's packages in `dist/*-licenses.json`), and the crates the binary links (cargo-about over `Cargo.lock`; `about.toml` lists the accepted licences in order of preference, `about.hbs` the layout). `pixi run licenses` regenerates it, the pre-commit hook does so when a lockfile or an input changes, and CI's `lockfile` job fails when it is stale. A package or crate under a licence the plugin's `allow` or `about.toml` does not list fails the run: accept the licence there on purpose, or drop the dependency.
- `pixi.toml` locks the toolchain from conda-forge, lefthook included, and its tasks are the entry points: `pixi run diffle <args>` is `cargo run` after the client build; `test-node`, `test-rust`, `e2e`, `lefthook-run`, `package`, `npm-packages` and `package-crate` are what CI runs, one task per job. The environment puts real language servers on PATH: `pixi run diffle working` reviews with them, `pixi run diffle lsp` lists what it resolves. Keep `pixi.lock` committed; run `pixi lock` after editing the manifest.
- CI runs the tests and the build on Linux, macOS, and Windows, x64 and arm64. Skip what Windows cannot express (`#[cfg(unix)]`, `skipIf`), with a note: a `"` or a newline in a filename, POSIX mode bits, a POSIX-shell probe.
- Remove temp directories with `rmTmp` from `test/tmp.ts`: an idle `cat-file --batch` holds the repo root as its cwd, and Windows refuses to remove it until the child is reaped.
- Comments explain why in one or two lines. Exported doc comments state contracts, not implementations.

## Commit gate

- `.lefthook.yml` defines the pre-commit hook: `npm run format`, `npm run lint` and `cargo fmt` over the staged files, then `npm run typecheck`, `cargo clippy` (when Rust or the generated contract changed) and `npm run quality-gate` over the whole working tree. It is not installed automatically (`no_auto_install`); run `pixi run lefthook-install` once per clone, and commit from a shell where lefthook is on PATH (`pixi shell`). The CI `lint` job runs `pixi run lefthook-run`, the same hook over every file, where `fail_on_changes` turns a formatter rewrite into a failure, so a `--no-verify` commit still fails there.
- A source file (`.rs` included, minus everything from its first `#[cfg(test)]` line) stays within 330 lines, and a folder holds at most 15 source files. Tests (`*.test.*`, `*.spec.*`, and files under `test`, `tests`, `__tests__`, `e2e`, `fixtures`, `testdata`, `__snapshots__`), generated files, package roots and the repository root are never counted. Nothing requires a test for new code.
- Split along a real responsibility, never a line-count saw-cut. The only way past the gate is `.locignore` (files) or `.folderignore` (folders), one glob per line with `#` comments: a pattern without `/` matches the basename, one with `/` the whole path. List only a cohesive unit (generated code, a data catalog), with the reason on the same line. A `TODO` entry is debt: delete it when its file shrinks under the cap.

## Conventional commits

- Use conventional commits for commit messages and PR titles (e.g. `feat(cli): add pr command`, `fix(store): guard async commits`).
- Squash-merged PR titles become `CHANGELOG.md` entries and pick the next version (`cliff.toml`): a `!` bumps the minor version before 1.0, anything else the patch. The Release workflow keeps a `chore: release vX.Y.Z` PR open; merging it tags the release, and the tag publishes it: the binaries and installers on the GitHub release, and the npm packages (`scripts/npm-packages.ts` assembles the launcher in `npm/` and one package per platform from the release archives; CI assembles and smoke-tests them on every PR), and the crate on crates.io (`scripts/package-crate.ts` packs it with the client build and the licence files, all git-ignored in `crates/diffle/`; CI packages and compiles it on every PR). Never edit `CHANGELOG.md` or the version by hand.
